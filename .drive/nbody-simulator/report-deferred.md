# 미룬 것 — nbody-simulator

`spec.md` 「미룬 것」 구획을 옮기고 항목마다 이유를 붙였다.
**다음 판을 시작할 때 이 목록을 먼저 꺼내 본다.**

---

## 기능

| 항목 | 미룬 이유 |
|---|---|
| **초신성 피드백** | 별 형성까지가 이번 범위였다. 피드백은 물리 모델이 한 겹 더 깊고(에너지 주입·충격파 되먹임) 튜닝 항목이 크게 는다 |
| **동영상 인코딩 내장** | 외부 의존성을 늘리지 않기로 했다(design.md O4). PNG 시퀀스로 뽑고 합치기는 외부 도구 몫 |
| **냉각 테이블**(실제 원소별 냉각률) | 단순 멱함수로 시작. 실제 테이블은 외부 데이터 파일 의존이 생긴다 |
| **설정 저장·불러오기**(프리셋 파일) | 기본 프리셋 5종으로 충분하다고 판단. 써 보고 필요하면 추가 |

## 성능·구조

| 항목 | 미룬 이유 |
|---|---|
| **CUDA↔OpenGL interop** | 지금은 호스트를 거쳐 화면 크기(약 5.8 MB)만 옮긴다. 예산의 6% 수준이라 급하지 않고, 교체는 `RenderField` 안에서 끝난다. **1000만 파티클 153.6 FPS 로 목표(60)를 크게 넘어 실익이 낮다** |
| **Unity 컴퓨트 셰이더 스택 측정** | CUDA 로 확정돼 비교 실익이 없다. 이식이 필요해지면 그때 |

## 승인 없이 이번 범위로 **편입한** 것

drive 규칙상 사용자가 승인하지 않고 넘어간 범위 변경은 반드시 눈에 보여야 한다.

| 항목 | 편입 시점 | 왜 편입했나 |
|---|---|---|
| **앱 제어 MCP 서버**(`mcp/server.js` 도구 11개) | round-01 도중 | 사용자가 대화 중 요청("mcp도 만들어서 테스트할때 사용해"). 창 있는 앱은 스크린샷 외 자동 검증 수단이 없어 8번 칸 QA 정확도가 여기 묶였다 — 진행이 막히는 쪽이라 편입 |
| **제어 채널 회귀 테스트**(`mcp/bridge-test.js`) | round-07 증분 1 | 회귀 24건은 `Sim` 을 직접 부르고 MCP 시나리오는 `set → preset` 순서라, **UI·브릿지 구간을 지키는 검증이 하나도 없었다**. 그 구멍이 P1 세 건을 다섯 바퀴 동안 숨겼다 |

## 리뷰가 지적했으나 이번에 안 고친 것 (P2)

게이트를 막지 않아 남겼다. 전부 `round-06-review.md` 에 위치와 함께 있다.

- `Sim.cu` — 격자 크기 2의 거듭제곱 미검증(#18) · CFL 이 가속 전 속도만 봄(#20) ·
  최대속력이 숨은 슬롯 포함(#21) · 별 온도가 같은 스텝에 다시 가열(#22) ·
  측정이 `rho` 를 갱신 안 함(#23) · 일시정지 중 편집이 화면에 즉시 반영 안 됨(#24) ·
  정렬 시간이 항상 0 으로 보고(#25)
- `main.cpp` — ImGui 백엔드 초기화 실패 무시(#28)
- `ControlBridge.cpp` — 응답 파일 교체 실패 무시(#32) · 제어 디렉터리 생성 실패 후에도 준비 상태(#33)
- `server.js` — 인스턴스가 같은 제어 디렉터리 공유(#34) · spawn `error` 미처리(#35)
- `bench-10m.js` — 클램프로 1000만 미달이면 예산 실패를 판정에서 제외(#37)

**#25(정렬 시간 0)와 #21(숨은 슬롯 속력)은 다음 판에서 먼저 볼 만하다** —
전자는 성능 화면이 거짓을 보여주는 것이고, 후자는 지우개를 쓴 뒤 CFL 이 과도하게 조여질 수 있다.
