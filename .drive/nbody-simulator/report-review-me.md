# 봐줬으면 하는 것 — nbody-simulator

내가 그 자리에서 스스로 골라 진행한 것들과, 사람만 확인할 수 있는 것들이다.
각 항목에 **뒤집을 근거**(무엇을 보면 내 선택이 틀렸다고 판단할 수 있는지)를 붙였다.

---

## A. 일하는 방식에서 반복된 문제

### A1. 판정 지표를 이 판에서 **7번** 고쳤다 — 가장 값진 항목

측정하려는 양이 그 시나리오·그 조건에서 **실제로 드러나는지**를 먼저 보지 않고 지표를 정한 탓이다.

| 회차 | 무엇을 재려다 | 처음 쓴 지표 | 왜 못 갈랐나 |
|---|---|---|---|
| round-04 | 중력 우물이 물질을 모으는가 | 최대밀도 | 우물이 넓게 모으면 국소 최고점은 오히려 내려간다(4876 → 3016) |
| round-05 | 냉각이 듣는가 | 최대밀도 → 점유셀 | 냉각의 1차 효과는 온도다. 밀도 변화는 2차라 경계·CFL 에 묻힌다 |
| round-05 | 팽창이 듣는가 | 최대밀도 | 같은 이유 — 점유셀로 바꿔 해결 |
| round-06 | QA 4항목 | `steps`·`msFrame`·`msScatter`·`gridMass` | **없는 필드 이름을 지어냈다.** 실제는 `simTime`·`frameMs`·`scatterMs`·`totalMass` |
| round-07 | 소프트닝(회귀) | 구조형성 프리셋 밀도 → 나선팔 → 정지덩어리 250스텝 | 안 뭉침(9.21 동일) → 궤도속도가 상쇄(6%) → 밀도가 격자 해상도에 포화(43.6 동일) |
| round-07 | 컬러맵 | 전체 화면 평균색 | 우측 설정 보드의 청회색이 섞였다. **세 컬러맵의 표본 픽셀 수가 25107 로 똑같이 나온 것**이 단서 |
| round-07 | 소프트닝(QA) | 구조형성 프리셋 | **회귀 테스트 주석에 이미 적어 둔 함정을 QA 에서 그대로 되밟았다** |

**공통 규칙 후보:** 지표를 쓰기 전에 ①그 양이 이 조건에서 유의미한 크기로 변하는가 ②변화가 다른 효과(CFL·궤도속도·포화·화면 UI)에 상쇄되지 않는가 ③검증 대상의 실제 인터페이스를 열어 이름을 확인했는가 — 셋을 먼저 본다.
**뒤집을 근거:** 이 규칙을 넣어도 8번째가 나면 규칙이 아니라 절차(예: 지표마다 사전 사감도 측정)를 바꿔야 한다.

### A2. 다섯 바퀴 동안 어느 게이트도 「보드가 안 먹는다」를 못 잡았다

회귀 테스트 24건은 `Sim` 을 직접 부르고, MCP 시나리오는 전부 `set → preset` 순서라
`nbody_preset` 이 뒤늦게 반영해 줬다. **두 검증 수단이 모두 UI·브릿지 구간을 건너뛰고 있었다.**
round-07 에서 `mcp/bridge-test.js` 를 만들어 그 구간을 지키게 했다.
**뒤집을 근거:** 브릿지 테스트가 7건뿐이라 여전히 구멍이 있을 수 있다. 보드 위젯 자체(ImGui 클릭)는 아직 어떤 테스트도 안 탄다.

## B. 내가 스스로 고른 설계 — 사람이 다르게 볼 수 있는 것

### B1. `needApply` 플래그를 없애고 매 프레임 코어에 동기화
위젯마다 "바뀌었으니 반영하라"를 손으로 켜는 구조라 17군데가 빠져 있었다. 표시를 빠뜨릴 수 있는
구조 자체를 지웠다. 비용은 `SimConfig` 복사 + `cudaMemGetInfo` 1회/프레임.
**실측**: 1000만 파티클 153.6 FPS 로 round-06(148.55)와 차이 없음 — `round-07-qa.md` Q5.
**뒤집을 근거:** 더 무거운 설정(격자 8192 등)이 생기면 매 프레임 클램프 계산이 부담이 될 수 있다. 그때는 `App` 이 직전 값과 비교해 바뀐 프레임만 넘기는 쪽으로.

### B2. 배속 > 1 을 프레임당 스텝 반복으로 냈다
CFL 은 안정성 한계라 dt 를 늘릴 수 없다. 대신 한 프레임에 여러 번 돈다 — **계산량이 그 배수로 는다.**
**중요한 한계:** GPU 가 이미 포화면 벽시계 시간당 진행량은 거의 안 는다(1.5초에 1.0x=0.012930 / 3.0x=0.015830, 1.22배). 프레임 수가 함께 줄기 때문이다.
**뒤집을 근거:** 사용자가 기대하는 "배속"이 *화면이 빨리 흐르는 것*이라면 이 구현은 무거운 설정에서 기대를 못 채운다. 그 경우 대안은 렌더를 건너뛰고 스텝만 여러 번 도는 것(프레임률을 희생).

### B3. 주기 경계 소프트닝을 주파수공간 가우시안으로 넣었다
`exp(-0.5·k²·s²)`, `s = 2π·softeningCells/G`. 고립 경계의 실공간 그린함수(`-1/max(r,eps)`)와는
수식이 다르다 — 두 경계에서 같은 슬라이더 값이 정확히 같은 물리를 주지는 않는다.
**뒤집을 근거:** 경계를 바꿔 가며 비교하는 실험을 한다면 두 경계의 소프트닝을 같은 스케일로 맞춰야 한다.

### B4. 냉각·팽창 계수를 ×3000 / ×6000 으로 키웠다 (round-05)
CFL 클램프로 dt 가 1e-5 수준이라 시간 비례 항이 0 에 수렴했다. 물리적 비례(dt 비례)는 유지하되
슬라이더를 올렸을 때 사람이 체감할 크기로 맞춘 것이다. **이 숫자에 물리적 근거는 없다.**
**뒤집을 근거:** 실제 냉각률·허블 상수와 대응시키려면 무차원화를 다시 해야 한다.

### B5. 점 렌더의 밀도 모드 대표색
밀도 모드는 겹침이 밝기를 만들므로 점마다 같은 색을 쌓는다. 그 색을 컬러맵에서 뽑았다 —
천체=보라, 흑백=흰색, 열화상=`cmapThermal(0.62)`.
**뒤집을 근거:** 열화상의 0.62 는 내가 고른 값이다. 다른 지점이 더 자연스러울 수 있다.

## C. 사람이 직접 봐야 하는 것 — 자동으로 확인 못 함

MCP 는 앱 내부 상태를 조작하므로 **ImGui 위젯 클릭 자체는 태우지 못한다.**

- 설정 보드 **접기/펼치기** 버튼
- 보드의 버튼들 — **📷 스냅샷 저장 · 최대치로 맞추기 · 녹화 시작/정지 · 안내 지우기**
  (파일 산출은 `nbody_screenshot`·`nbody_record` 로 확인됨 — round-06 I1·I2)
- **창 크기 조절**(`WM_SIZE`) 후 화면 유지
- 마우스 **드래그**로 뿌리기·우물·지우개 (좌표 API 로는 확인됨 — round-06 G2~G6)

### C1. 설정 보드가 1600×900 에서 세로로 넘친다
9섹션 중 **「프리셋·녹화·성능」 3섹션이 스크롤 아래**에 있다. 성능 막대를 보려면 스크롤해야 한다.
**뒤집을 근거:** 시안(`design-mockup.html`)이 스크롤을 전제했는지, 아니면 섹션을 접어 둘 것을 전제했는지 확인 필요.
