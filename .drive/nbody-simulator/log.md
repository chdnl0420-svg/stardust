## 덩어리 1 (턴 1~5)

### 사용자 최초 요청
> Ndbody 시뮬레이터 만들어줘. 몇백만 몇천만 파티클이 서로 중력공식에 따라 동작하는걸 볼수있는 시뮬레이션이야.

### 던진 재료 — 규모가 "서로"의 뜻을 바꾼다
- 천만 개를 전수로 서로 당기면 쌍이 5×10¹³ 개. 프레임 하나에 며칠.
- 이 규모를 실시간으로 돌리는 것들은 전부 근사를 쓴다 — Barnes-Hut 트리(멀리 있는 덩어리를 점 하나로), 또는 PM(격자에 밀도를 뿌려 FFT로 포아송 풀기).
- 근사가 타협처럼 들리지만 실제 우주론 시뮬레이션도 똑같이 한다.
- 방식이 보이는 그림을 바꾼다 — 트리는 별 하나하나가 튕기는 게 보이고, 격자는 거대 필라멘트 구조가 자라는 게 보인다.

### 사용자 답
> 다른 사람들은 보통 쿼드트리를 이용해서 최적화를 하더라고. 나는 은하가 휘감기고 충돌하는것도 보고싶고 내가 초기조건 던저놓고 저절로 생기는지 보는것도좋아 실제 우주의 입자가 중력에의해 서로 모이고 부딛히는걸 보고싶어. 중력과 유체역학 적용해서 만들어줘.

→ 나온 것: 쿼드트리 언급 / 은하 충돌 장면 + 초기조건 실험 **둘 다** 원함 / 중력 + 유체역학 둘 다 적용

### 던진 재료 — "부딪힌다"에 물리가 두 개 겹쳐 있다
- 은하가 정면충돌해도 별끼리는 거의 안 부딪힌다. 별 사이 거리가 별 지름의 천만 배. 서로 통과하고 중력으로만 휘젓는다.
- 나선팔이 늘어지고 조석 꼬리가 뻗는 극적인 그림은 전부 "안 부딪히는" 충돌이 만든다.
- 진짜 부딪히는 건 가스. 가스구름은 통과 못 하고 정면에서 충격파를 만들며 압축되고, 그 자리에서 별이 폭발적으로 태어난다.
- 중력+유체가 정석 조합인 이유. 실제 우주론 코드(GADGET·GIZMO)가 그 둘을 얹는다.
- 파티클이 두 종류로 갈린다 — 통과하는 것(암흑물질·별) / 부딪히는 것(가스).

### 사용자 답
> 전부 가스로 두고 실제 부딪히는건아니고

→ 나온 것: 파티클 종류는 **가스 하나만**. 강체 충돌 판정은 원하지 않음.

### 던진 재료 — 그게 SPH 그 자체
- SPH에는 충돌 판정이 아예 없다. 겹치려 하면 밀도가 오르고, 밀도가 오르면 압력이 밀어낸다.
- "부딪힘"이 아니라 "밀림"이라 파티클이 몇 개든 로직이 안 늘어난다.
- 충격파 전선도 밀림이 쌓여 저절로 생기는 것. 코드 어디에도 "부딪혔다" 판정이 없다.

### 던진 재료 — 차원 갈림 (쿼드트리는 2D 전제)
- 2D: 천만 개가 수월, 화면이 파티클로 꽉 차 화려. 원반이 기울어 보이거나 필라멘트가 앞뒤로 뻗는 입체감은 없음.
- 3D: 옥트리. 확 무거워지는 대신 진짜 우주처럼 보임.

### 사용자 답
> 2D로 할꺼야.

→ 나온 것: **2D 확정**.

### 던진 재료 — 2D 중력 지수 문제
- 진짜 2D 우주(무한히 긴 실린더 세계)의 중력은 1/r. 우리가 아는 1/r²는 3D 전용 공식.
- 1/r: 멀리서도 힘이 안 죽어 판 전체가 한 덩어리로 붕괴하려 듦.
- 1/r²: 가까운 것끼리만 뭉쳐 덩어리가 여럿 생기고 그것들이 서로 돌며 나선을 만듦.
- 내 의견 = 1/r². "3D 우주를 위에서 눌러 본 것"이라는 감각이 원하는 그림에 가깝고, 은하 나선팔이 실제로 그렇게 생긴다.
- (아직 사용자 답 없음 — 열려 있음)

### 사용자 답 — 하드웨어
> RTX 3070 Ti 를 사용중이야. (스크린샷: NVIDIA GeForce RTX 3070 Ti, VRAM 8017 MB, 전체 메모리 근사값 45010 MB)

### 던진 재료 — 트리 vs 격자 (GPU 관점 반대편 찌르기)
- 3070 Ti면 천만은 넉넉. 파티클당 40바이트로 400MB = 8GB VRAM의 5%. 메모리는 문제 아니고 병목은 이웃 탐색·트리 순회.
- 트리는 GPU가 제일 싫어하는 자료구조 — 포인터 추적, 워프 내 32스레드가 서로 다른 깊이로 갈라짐, 매 프레임 재구축 비용.
- CPU에서 쿼드트리가 정석인 건 맞지만 GPU에서는 얘기가 다름.
- 2D 대안: 격자에 질량 뿌리고 FFT로 포아송 한 번에 풀기(PM). GPU가 좋아하는 형태이고, **SPH 이웃 탐색에 어차피 필요한 격자를 그대로 재활용** — 자료구조 하나로 중력과 유체를 둘 다 먹는다.
- 대가: 격자 칸보다 작은 스케일의 중력이 뭉개짐. 별 두 개가 서로 도는 건 안 보이고 큰 구조만 보임.
- (사용자 답 대기 중)

### 아직 안 건드린 것 (열린 채로 굴러다니는 재료)
- 기술 스택 — 유니티 컴퓨트 셰이더 / 네이티브 C++ + CUDA / 브라우저 WebGPU 중 무엇
- "본다"의 형태 — 실시간 인터랙티브(카메라 줌·팬, 초기조건 조작) vs 렌더링해서 영상으로
- 렌더링 표현 — 점 하나씩? 밀도 필드로 뭉개서? 온도 색깔?
- 시간 스텝 — SPH는 CFL 조건에 묶여 중력만 할 때보다 훨씬 잘게 쪼개야 함
- 초기조건 종류 — 은하 원반 두 개 충돌 / 균일 난수에서 구조 형성 / 사용자가 마우스로 뿌리기
- 경계 조건 — 무한 공간? 주기 경계(반대편으로 넘어감)? 벽?

## 덩어리 2 (goal 갈래 — 계산 방법 선정)

발산 대화 도중 사용자가 `/CAP:create-goal-prompt` → `/goal` 로 별도 갈래를 열었다.
"세상에 없는 가장 좋은 방법을 찾아낼 때까지 고민하고, 점수를 매겨 기존 방법과 비교해 최고점을 선택하라."
이 갈래에서 나온 결과가 위 「아직 안 건드린 것」 중 **기술 스택**과 **경계 조건** 재료를 상당 부분 채웠다.

전체 기록은 `method-search/` 네 문서에 있다. 여기엔 **대화로 되돌아올 재료만** 남긴다.

### 이 갈래에서 확정된 것 (실측 근거 있음)
- 승자: **X1 단일 격자 융합 × CUDA** (총점 6.35). 하나의 2D 격자에 중력(FFT 포아송)과 가스 압력을 함께 얹어 SPH 이웃 탐색을 파이프라인에서 제거.
- N=10M 실측: X1 **2.3 ms/step (435 FPS)** vs 기존 표준 B3(PM+SPH) **23.1 ms (43 FPS)**.
- N=30M 추정: X1 5.2 ms 통과 / B3 68 ms 예산 초과 → **"몇천만"까지 올리면 기존 표준은 탈락한다.**
- 병목은 중력이 아니라 **캐시 지역성**이었다. 파티클을 셀 순서로 정렬하면 산란이 8.5배 빨라진다(44.19 → 4.88 ms).
- 정렬 주기 K=40 실측 — X1은 40스텝까지 재사용 가능, SPH는 매 스텝 필수(6.5 ms 고정 지출).
- FFT 포아송 4096² = 2.36 ms. 멀티그리드 문헌값(93 ms)의 1/40 → 멀티그리드 후보 탈락.
- 2D 격자에서 3D형 1/r² 중력을 얻으려면 주파수공간에서 **1/k** 를 곱한다(1/k² 는 진짜 2D의 1/r 힘).
- 메모리: 단일 2048 MiB 버퍼, 누적 5504 MiB 확보 → 1억 개 이상 수용 가능.

### 이 갈래에서 눈으로 확인한 것
- **구조 형성: 완전 성공** — 헤일로·필라멘트·보이드의 우주 거미줄 재현 (`proto/out2/structure.png`)
- **나선팔: 부분 성공** — 막대(bar) 구조·클럼프는 나오나 나선팔 미유지 (`proto/out3/spiral.png`)
- **조석 꼬리: 실패** (3회 시도) — 초기 궤도 파라미터 미조정. 알고리즘 한계 아님
- **충격파 전선: 실패** (3회 시도) — 압력계수를 중력 스케일에 미보정. **X1의 유체 부분은 아직 미증명**

### 이 갈래가 새로 열어 놓은 재료 (대화로 되돌릴 것)
- **경계 조건이 시나리오마다 다르다는 것이 드러났다.** 은하(고립) vs 우주 구조형성(주기).
  고립은 zero-padding 때문에 FFT 격자가 4배(4096²→8192², 약 9.4 ms 추정). 둘 다 지원할지, 하나만 할지.
- **격자 해상도가 곧 물리 해상도다.** 1024²/2048²/4096² 중 무엇을 기본으로 둘지가 "무엇이 보이는가"를 정한다.
- **압력(가스다움)을 어느 정도로 넣을지가 미해결.** 압력을 0으로 두면 나선팔·조석꼬리·구조형성은 나오지만
  "부딪히는" 느낌은 사라진다. 사용자가 원한 것은 후자였다.
- **인터랙션 범위** — 카메라 줌·팬만? 초기조건을 마우스로 뿌리기? 파라미터 실시간 조절?
- **B3(기존 표준)를 완전히 버릴지** — 그림 축을 B3에 안 돌린 것이 순위를 갈랐다는 사실이 기록에 남아 있다.
