## 결정사항

### A. 무엇을 만드는가

| # | 결정 | 출처 |
|---|---|---|
| A1 | **실시간 인터랙티브 데스크톱 앱**. 창을 띄워 지금 돌아가는 걸 보면서 조작한다 | 인터뷰 Q1 = "1+3" |
| A2 | **녹화 기능 포함.** 마음에 드는 장면에서 눌러 저장한다 | 인터뷰 Q1 = "1+3" |
| A3 | 조작 범위는 **샌드박스** — 카메라 줌·팬 + 프리셋 + 실시간 슬라이더 + **마우스로 돌아가는 중에 직접 개입** | 인터뷰 Q2 |
| A4 | **마우스 클릭으로 형태(덩어리·원반)를 추가**할 수 있어야 한다 | 인터뷰 Q5 = "마우스로 클릭해서 형태를 추가도 할수있게" |
| A5 | **화면에서 열고 닫는 설정 보드**를 둔다. 거기서 수치 조정과 기능 on/off를 한다 | 인터뷰 Q6 = "열고 닫을수있는 설정 보드" |

### B. 무엇을 계산하는가

| # | 결정 | 근거 |
|---|---|---|
| B1 | 계산 방법 = **X1 단일 격자 융합** (하나의 2D 격자에 중력 FFT 포아송 + 가스 압력, 이웃 탐색 없음) | 실측 선정, 총점 6.35 |
| B2 | 스택 = **네이티브 CUDA** (13.3.1 설치 완료, cuFFT + CUB) | 실측: WebGPU 대비 산란 3배 |
| B3 | 중력 = **1/r² 기본**, 1/r(진짜 2D)로 **전환 가능** | 인터뷰 Q4. 주파수공간 나눗셈 한 줄이라 비용 사실상 0 |
| B4 | **압력은 핵심 기능.** 압력계수를 중력 스케일에 맞춰 **실측 보정**하고, 충돌면에 밀도 불연속(충격파 전선)이 서는 것을 스크린샷으로 확인해야 완료 | 인터뷰 Q3. 현재 미증명 상태 해소가 스펙에 포함됨 |
| B5 | 경계 조건 = **고립·주기 둘 다**, 프리셋별로 맞는 것을 쓴다 | 인터뷰 Q3. 은하=고립, 구조형성=주기 |
| B6 | **파티클을 셀 순서로 주기적 정렬**한다 (성능이 여기 달렸다) | 실측: 정렬 시 산란 8.5배, 40스텝 재사용 가능 |

### C. 리얼함 — 전부 넣되 전부 끌 수 있게

인터뷰 Q6 = "1,3 다하는데 ... 기능 온오프 할수있게".
**아래 전부를 구현하고, 각각을 설정 보드에서 개별 on/off 한다.**

| # | 기능 | 켜면 무엇이 달라지나 |
|---|---|---|
| C1 | 스플라인 소프트닝 | 가까운 거리의 힘이 더 정확해진다 |
| C2 | **우주 팽창** | 구조 형성이 실제 우주의 역사대로 진행된다(팽창과 중력붕괴가 경쟁) |
| C3 | **온도 추적** | 부딪힌 자리가 달아올라 **색으로 보인다** — B4(충격파 실증)와 직결 |
| C4 | 복사 냉각 | 가스가 식으며 뭉쳐 별 씨앗이 생긴다 |
| C5 | 별 형성 | 조건을 만족한 가스가 별로 바뀌어 은하가 진화한다 |
| C6 | 압력 on/off | 끄면 무압력 중력계(나선팔·조석꼬리·구조형성 검증 영역)로 돌아간다 |

### D. 무엇을 보여주는가

| # | 결정 |
|---|---|
| D1 | 렌더링은 **밀도 필드 + 파티클 점을 둘 다 구현하고 전환**한다 |
| D2 | 초기조건 프리셋 = **검증 4종**(회전원반=나선팔 / 두 원반 스침=조석꼬리 / 정면충돌=충격파 / 균일난수=구조형성) **+ 빈 판** |
| D3 | 빈 판에서 **마우스로 형태를 추가**해 직접 초기조건을 만든다 (A4) |

### E. 완료 기준

| # | 기준 | 판정 방법 |
|---|---|---|
| E1 | **파티클 1000만 개에서 60 FPS** (프레임 예산 16.7 ms) | 앱 내 프레임 시간 표시 + 스크린샷 |
| E2 | 충격파 전선이 실제로 선다 | 충돌면 밀도 불연속 스크린샷 |
| E3 | 설정 보드의 모든 토글이 실제로 동작한다 | 켠 상태/끈 상태 스크린샷 대조 |
| E4 | 프리셋 4종이 각각 의도한 현상을 만든다 | 현상별 스크린샷 |

기능을 끄면 1000만보다 더 올릴 수 있도록 설계한다(E1은 전 기능 on 기준이 아니라 기본 구성 기준).

### F. 인터뷰에서 답하지 않고 내가 정한 것 (근거 명시)

| # | 결정 | 근거 |
|---|---|---|
| F1 | 격자 해상도 **기본 2048²**, 설정 보드에서 1024²/2048²/4096² 전환 | 실측: 정렬된 상태에서는 격자를 16배 키워도 총시간이 늘지 않았다(5.758→4.212 ms). 2048²가 해상도와 FFT 비용(0.495 ms)의 균형점 |
| F2 | 시간 스텝은 **CFL 조건 기반 적응형 dt** + 프레임당 서브스텝 허용 | 압력을 켜면 음속에 묶여 고정 dt로는 폭발한다. 실시간 앱이므로 프레임당 스텝 수에 상한을 두고 dt를 CFL로 클램프 |
| F3 | 고립 경계는 **zero-padding 2배 격자 + 실공간 그린함수** 방식 | 라운드5에서 이 방식으로 배율 0.89~0.97(물리 정합) 확인. 대가는 FFT 격자 4배 |

### G. 명시적 제외 (이번 범위 아님)

- 3D — 사용자가 2D 선택
- 파티클 두 종류(암흑물질/별 + 가스 분리) — "전부 가스"
- 강체 충돌 판정 — 사용자가 명시적으로 배제
- Barnes-Hut·멀티그리드·PM+SPH — 실측 탈락 (근거는 scorecard.md)
- 초신성 피드백 — C5(별 형성)까지만. 피드백은 별개 판

## 열린 질문 (3번 칸에서 정한다)

| # | 질문 | 왜 지금 못 정하나 |
|---|---|---|
| O1 | 설정 보드에 정확히 어떤 항목이 어떤 순서로 들어가는가 | 기능 목록이 방금 확정돼 UI 구성은 설계 단계 일 |
| O2 | 별 형성의 판정 기준 (밀도 임계? 온도 임계? 둘 다?) | 물리 모델 선택이라 설계에서 근거와 함께 정해야 한다 |
| O3 | 복사 냉각 함수의 형태 (단순 멱함수? 냉각 테이블?) | 위와 같음. 비용과 리얼함의 트레이드오프 |
| O4 | 녹화 출력 형식 (이미지 시퀀스 / 동영상 인코딩) | 인코더 의존성 여부가 갈린다 |
| O5 | 마우스 개입 도구의 구체 목록 (뿌리기·중력우물·형태추가·지우개?) | A3·A4가 큰 틀만 정했다 |
| O6 | 창 해상도와 렌더 타깃 크기 | 격자 해상도와 별개로 정해야 한다 |
| O7 | 온도를 어떤 색으로 매핑할지 | D1(렌더링)의 하위 결정 |
| O8 | 기능을 다 켰을 때 1000만/60FPS가 실제로 유지되는지 | 온도·냉각·별형성 비용이 미측정이다. 설계에서 예산을 배분하고 구현 중 실측해야 한다 |
