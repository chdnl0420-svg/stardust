## 굳어진 것 (사용자가 동의했거나 실측으로 확정된 방향)

| # | 내용 | 근거 |
|---|---|---|
| 1 | **2D**로 만든다 | 사용자: "2D로 할꺼야." |
| 2 | 파티클은 **가스 한 종류**. 암흑물질/별을 따로 두지 않는다 | 사용자: "전부 가스로 두고" |
| 3 | **강체 충돌 판정을 쓰지 않는다.** 겹치면 밀도가 오르고 압력이 밀어내는 방식 | 사용자: "실제 부딪히는건아니고" |
| 4 | **중력과 유체역학을 함께** 얹는다 | 사용자: "중력과 유체역학 적용해서 만들어줘" |
| 5 | 보고 싶은 것이 **둘 다** — 은하가 휘감기고 충돌하는 장면 **그리고** 초기조건 던져놓고 뭐가 생기는지 관찰 | 사용자: "은하가 휘감기고 충돌하는것도 보고싶고 내가 초기조건 던저놓고 저절로 생기는지 보는것도좋아" |
| 6 | 규모 **수백만~수천만** | 최초 요청 |
| 7 | 하드웨어 **RTX 3070 Ti / VRAM 8 GB** | 사용자 스크린샷 |
| 8 | 계산 방법 = **X1 단일 격자 융합** (하나의 2D 격자에 중력 FFT 포아송 + 가스 압력을 함께 얹어 이웃 탐색 제거) | goal 갈래 실측 선정, 총점 6.35 |
| 9 | 스택 = **네이티브 CUDA** (툴킷 13.3.1 설치 완료) | 실측: 산란이 WebGPU의 3배 빠름 |
| 10 | 중력은 **1/r² (3D형)**. 격자에서는 주파수공간 **1/k** 를 곱해 얻는다 | 내가 제안하고 goal 갈래에서 그대로 구현·검증. 사용자 명시 동의는 없었음 — 아래 「열린 것」 1번 참조 |
| 11 | 파티클을 **셀 순서로 주기적 정렬**한다 (성능이 여기 달렸다) | 실측: 정렬 시 산란 8.5배, 40스텝까지 재사용 가능 |

## 아직 열린 것 (갈렸거나 안 정한 것)

| # | 열린 질문 | 왜 열려 있나 |
|---|---|---|
| 1 | **중력 지수 1/r² 확정?** | 내가 1/r²를 추천했고 goal 갈래가 그걸로 구현했으나 **사용자가 명시적으로 답한 적이 없다.** 구현이 답을 대신한 상태 |
| 2 | **경계 조건** — 고립 / 주기 / 둘 다 | 시나리오마다 다르다는 것이 실측으로 드러났다. 은하=고립, 우주 구조형성=주기. 고립은 FFT 격자 4배(약 9.4 ms 추정) |
| 3 | **격자 해상도 기본값** (1024² / 2048² / 4096²) | 격자 해상도가 곧 물리 해상도라 "무엇이 보이는가"를 정한다. 셋 다 예산 안에 들어옴 |
| 4 | **압력 세기(가스다움)를 어느 정도로** | 압력 0이면 나선팔·조석꼬리·구조형성은 나오지만 "부딪히는" 느낌이 사라진다. 사용자가 원한 건 후자 |
| 5 | **"본다"의 형태** — 실시간 인터랙티브 vs 렌더링해서 영상 | 아직 대화에 안 나옴 |
| 6 | **인터랙션 범위** — 카메라 줌·팬만? 마우스로 파티클 뿌리기? 파라미터 실시간 조절? | 아직 대화에 안 나옴 |
| 7 | **렌더링 표현** — 점 하나씩 / 밀도 필드로 뭉개서 / 온도·속도 색깔 | 아직 대화에 안 나옴 |
| 8 | **초기조건 프리셋 종류** | 검증에 쓴 4종(회전원반·스치는 두 원반·정면충돌·균일난수)이 그대로 프리셋 후보 |
| 9 | **충격파를 살릴 것인가** | X1의 유체 부분이 3회 시도 모두 실패해 **미증명**. 압력계수를 중력 스케일에 맞춰 실측 보정하는 작업이 남음 |
| 10 | **시간 스텝 제어** | 압력을 켜면 CFL 조건에 묶여 잘게 쪼개야 한다. 고정 dt로 갈지 적응형으로 갈지 |

## 버린 것과 버린 이유

| 버린 것 | 이유 |
|---|---|
| **3D** | 사용자가 2D를 골랐다. 3D면 옥트리·27셀 순회로 비용이 몇 배가 되고 격자 해상도를 못 올린다 |
| **파티클 두 종류(암흑물질/별 + 가스)** | 사용자가 "전부 가스로" 선택. 통과하는 것과 부딪히는 것을 나누지 않는다 |
| **강체 충돌 판정** | 사용자가 명시적으로 배제. SPH·격자 압력 방식은 애초에 충돌 판정이 없다 |
| **Barnes-Hut 쿼드트리** | 사용자가 처음 언급했으나 실측 탈락 — 문헌 500만 바디 1509 ms로 목표 대비 45배 이상. GPU에서 트리는 워프 발산·포인터 추적으로 불리 |
| **멀티그리드 포아송** | FFT 실측 2.36 ms가 멀티그리드 문헌값 93 ms를 40배 앞서 존재 이유가 사라짐 |
| **B3 (PM + SPH) — 기존 표준** | X1의 약 10배 비용(23.1 vs 2.3 ms). 3000만에서는 예산 초과. **단 그림 축을 B3에 돌리지 않은 것이 순위를 갈랐다는 사실이 기록에 남아 있다** |
| **WebGPU 스택** | CUDA가 산란 3배 빠름(f32 atomic 네이티브 지원 차이). **완전 폐기는 아니다** — 절대값으로는 예산 안에 들어오므로 "설치 없이 공유"가 중요해지면 되살릴 수 있다 |
| **1/k² 커널 (진짜 2D 중력)** | 그건 힘이 1/r이라 판 전체가 한 덩어리로 붕괴하려 든다. 원하는 그림(덩어리 여럿 + 나선)은 1/r²에서 나온다 |
