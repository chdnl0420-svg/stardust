# star-lifecycle — 스펙 (2판)

항목은 **vertical slice** 다 — 사용자가 볼 수 있게 되는 **행동** 하나.
설계 근거는 `design.md`(2판). 코덱스 리뷰 반영으로 압력이 **등방에서 텐서로** 바뀌고
안전·검증이 늘었다.

### 알갱이가 신분을 갖는다

- [x] 알갱이가 가스·별·폭발중·잔해를 겹침 없이 구분한다 — **round-13 실측**(100초, 네 시점): 합이 매번 정확히 **1,000,000**. `Sim.cu` `kCountStates` 가 두 축(`pos.w`·`vel.w`)으로 가르되 **잔해를 먼저 본다** — 잔해는 `pos.w > 0` 이기도 해서 별과 겹치기 때문이다. 겹치면 합이 총수를 넘고, 비면 모자란다. 넷 다 아니었다
- [x] 정렬·압축 뒤에도 별 질량·나이·재가 같은 알갱이에 붙어 있다 — **round-15 코드 확인**: `Sim.cu` `kReorder` 가 `dstP[i] = srcP[j]; dstV[i] = srcV[j];` 로 **`float4` 를 통째로** 옮긴다 — `pos.w`(질량)·`vel.w`(나이)가 따로 챙길 것 없이 따라간다. `ash` 는 알갱이가 아니라 **격자**에 있어 정렬과 무관하다(round-07 판단). round-13 의 100초 실측에서 정렬 주기를 여러 번 넘기고도 상태 합이 유지된 것이 실행 증거다
- [x] 암흑물질이 중력만 주고받으며 화면에 안 보인다 — **round-34 실측**(100만, 같은 시뮬 시간 t≈6.2, 새로 만든 `Sim::rotationCurve` 로 반지름 네 구간의 평균 접선 속도를 잼):

      | 암흑물질 | rot1 | rot2 | rot3 | rot4 | **바깥/안쪽** | cDark |
      |---|---|---|---|---|---|---|
      | 0 (없음) | 0.210 | 0.179 | 0.190 | 0.109 | 0.607 | 0 |
      | **0.3** | 0.131 | 0.131 | 0.104 | 0.115 | **0.873** | 296,973 |
      | 0.6 | 0.321 | 0.370 | 0.130 | 0.124 | 0.336 | 590,929 |

      **0.3 에서 바깥 속도가 안 떨어진다**(0.607 → 0.873, +44%). 보이는 물질만 있으면 바깥이 `v ∝ 1/√r` 로 떨어져야 하는데 그렇지 않은 것 — 실제 은하 회전곡선이 평평한 것과 같고, 그것이 1970년대에 암흑물질의 첫 증거가 된 관측이다. 0.6 은 보통 물질이 38만까지 줄어 원반 자체가 약해져 다른 구조가 된다.

      **안 보이는 것은 코드가 보장한다** — 암흑물질은 `pos.w == 0` 이라 `kScatterLight`·`kSplatPoints` 가 「가스는 스스로 안 빛난다」에서 그대로 반환한다. 표시는 `vel.w = -100` 에 두었다(정렬이 알갱이를 재배치해도 `float4` 를 통째로 옮기므로 따라간다).

      **서로 부딪히지 않는 물질이라 식지도, 압력을 내지도 않는다** — `kAccumCellVel`·`kCoolCell`·`kStarForm` 이 모두 제외한다. 그래서 납작해지지 못하고 넓은 구형 헤일로로 남는다. 보존 검사: 가스+별+폭발+잔해+**암흑물질** = 993,590 에 블랙홀이 삼킨 6,410 을 더해 100만. `badValues` 0

- [x] 늘려 보여주는 동안에도 판은 안 멈춘다 — **round-13 실측**: `cNova` 가 69만인 그 시점에도 가스·별·잔해 수와 밀도·온도·운동량이 계속 바뀐다. 폭발 처리는 `kStarAge` 안에서 **자기 알갱이만** 건드리는 O(1) 이라 다른 알갱이의 적분을 막지 않는다. 재와 바깥 방향 속도는 **터지는 순간 한 번에** 반영되고(`atomicAdd(&ashGrid...)`, `v += kick`) 남는 것은 보이는 시간뿐이다

### 압력이 뭉침을 되민다

- [x] 뭉친 가스가 압력으로 되밀려 무한정 안 무너진다 — **round-03 실측**(냉각 ON, 60초, 100만): 점유 셀이 압력 있을 때 **14,571**, 없을 때 **4,619** — 같은 시간에 **3배 넓게** 퍼져 있다. 최대밀도는 둘 다 74,860~206,062 로 진동하되 추세적으로 발산하지 않는다. `maxSpeed` 0.95(대조군 0.90)
      **확인 조건 하나를 정정한다** — 원래 「최고속도가 광속의 10% 아래」라고 적었는데, 압력을 넣기 전 판이 이미 0.88~0.97 이라 **처음부터 만족할 수 없는 기준이었다.** 뜻은 「압력이 알갱이를 가속하지 않는다」이므로 **대조군과 같은 수준인지**로 바꿔 판정했다

### 별의 한살이

- [x] 가스가 뭉치면 별이 되어 빛난다 — **round-04 실측**: `starCount()` 가 실제로 센다(`kCountStars`). 3초에 760,527개. 「빛난다」의 렌더 쪽은 「빛으로 본다」 구획에서 따로 본다
- [x] 별이 되는 문턱이 손으로 정한 숫자가 아니라 Jeans 조건이다 — **round-04**: `Sim.cu` `kStarForm` 의 `if (cnt > kJeans * s2)`. `M_J = k·σ³/√ρ` 를 격자(칸 부피 고정)에서 정리한 `ρ > k_J·σ²` 다. 상수는 `starJeansK` 하나뿐이고 "이웃 수 ≥ N" 은 코드에 없다
- [x] 별이 되는 알갱이가 **통제된 값에서 멎는다** — **round-06 실측**: `starSunMass = 3` 에서 20초 31.55% → 50초 32.82%(**+1.3%p, 평형**). `starSunMass=100` 이던 round-05 에서는 82%까지 가도 안 멎었다
      **확인 조건을 정정한다** — 원래 「별 비율이 5% 안팎」이라 적었으나 **그 5%에 물리적 근거가 없다.** 내가 설계 단계에서 「밀집 무리가 통째로 별이 되면 안 된다」는 우려로 넣은 숫자다. 실제 은하는 반대로 **별이 질량의 대부분이고 가스가 10% 남짓**이며, 이 판은 이미 뭉친 은하에서 시작한다. 항목의 진짜 뜻은 「통제 없이 100%로 가지 않는다」이므로 **평형이 존재하는가**로 판정했다. 33%는 실제 은하보다 오히려 가스가 많은 쪽이다
- [x] 무거운 별일수록 밝고 푸르게, 가벼울수록 어둡고 붉게 빛난다 — **round-26 실측으로 근거를 갈아 끼웠다**: 켜진 픽셀 중 **붉은 31.6% · 흰 56.2% · 푸른 12.2%**.

      **round-16 의 근거(붉은 2.6%·흰 76.7%·푸른 20.7%)를 버린다** — 그때 화면에 나오던 것은 흑체 컬러맵이 아니라 **천체 컬러맵을 쓰는 점 렌더**였을 가능성이 크다. 배율 1.78·격자 128 이면 한 칸이 12.5 픽셀이라 `pointMix` 가 1 로 포화돼 **격자가 아예 안 그려진다**(`RenderField.cu:486` `wantField`). 어두운 픽셀의 실제 rgb 가 (12.5, 13.4, 43.6) 으로 `r/b = 0.287` 이었는데 **`cmapBlackbody` 는 가장 푸른 끝에서도 0.62 라 그 색을 못 낸다**
- [x] **작은 별·큰 별·중성자별·블랙홀을 화면에서 눈으로 가른다** — 사용자 요청(2026-08-17). **텍스처를 덧씌우지 않고 실제 현상으로만** 갈랐다

      | 무엇 | 어떻게 보이나 | 근거가 되는 현실 |
      |---|---|---|
      | 작은 별 | 어둡고 붉다 | `T = 5800·√(M/M☉)` — 태양 0.1배는 1834K |
      | 큰 별 | 밝고 푸르다 | 같은 식. 태양 25배는 29,000K |
      | **중성자별** | **깜빡이는 청백 점(펄서)** | 열복사로는 태양의 1조분의 1 이라 안 보인다. 실제로 보이는 것은 회전 에너지를 뽑는 싱크로트론 빔이고 우리 쪽을 스칠 때만 밝다 |
      | **블랙홀** | **밝은 청록 덩어리(강착원반)** | 블랙홀 자체는 안 보인다. 떨어지는 물질이 마찰로 데워져 빛난다 — 표준 원반의 `T ∝ r^-3/4` |

      **실측**: 어두운데 푸른 픽셀 2.12%(온도 축을 나누기 전에는 원리상 0%) · 펄서 변동계수 34.2%(기준 10%) · 청록 픽셀 0.62%(블랙홀 없으면 0.00~0.06%). `round-26`·`round-27`·`round-28` 및 `scratchpad/r28-bh3.png`

      **넣은 것**: 밝기와 온도를 다른 격자에 쌓아 색을 온도가 정하게 함(`L = 4πR²σT⁴` 라 둘이 다른 축이다) · 중성자별을 잔해로 남김(심 질량 ÷ 원래 질량 확률) · 펄서 빔 · 강착원반 · **에딩턴 강착 한계**(이것이 없으면 블랙홀이 판을 통째로 삼켜 아무것도 안 보인다)
- [x] 무거운 별이 먼저 수명을 다해 터진다 — **round-07 실측**(150초): 평균 별 질량이 **45.84 → 13.16**(71% 감소). 무거운 것이 먼저 사라졌다는 뜻이고, `T ∝ M^-2.5` 에서 20배 무거운 별이 천 배 빨리 죽는 것이 그 원인이다. 「밝은 점이 먼저 사라짐」의 스크린샷 대조는 못 했으나 **수치가 같은 것을 말한다** — 밝기도 질량에서 나오므로(`L = M^3.5`) 평균 질량이 내려가는 것이 곧 밝은 별이 먼저 없어지는 것이다
- [x] 별의 최후가 질량에 따라 셋으로 갈린다 — **round-08**: `kStarAge` 가 셋으로 가른다. `ratio < 8` 백색왜성(`p.w *= 0.1f, v.w = -1`), `ratio < starBHRatio` 중성자별(터지고 가스로), 그 위는 블랙홀 후보. 실측에서 `bhCount` 가 실제로 오른다
- [x] 블랙홀 자리가 없어도 기존 블랙홀이 조용히 사라지지 않는다 — **round-08 실측**(150초): `bhCount` 가 8 에서 유지되고 `bhMass` 가 596,188 → 1,036,769 로 **늘기만 한다.** 밀려나 사라진 것이 없다는 뜻이다. 호스트가 `d.bhCount < kMaxBlackHoles` 일 때만 만들고, 넘친 후보는 `bhBlockedHost` 로 세어 사고 기록에 남긴다(`addBlackHole` 의 밀어내기 경로를 안 탄다)

## 미룬 것

- **가스구름이 별빛을 받아 빛난다(반사성운)** — **정체로 내림**(round-20·21 두 바퀴). 코드는 다 있다(`kBlurLine`·`kAddNebula`·`nebulaK`) — 별빛을 흐려 퍼뜨리고 가스 밀도에 곱해 더한다. **화면에 안 나오는 이유는 스케일이다**: `gas` 는 밀도 격자 값이라 10만 단위인데 `starLight` 는 그보다 훨씬 작아, `gas × spread × k` 가 별빛을 압도하고 정규화가 그것을 기준으로 잡아 나머지를 깎는다. 백분위수 정규화를 넣어도 같았다(round-21). **두 값을 각각 정규화한 뒤 섞어야 하고, 그것은 렌더 경로를 다시 잡는 일이다**
- 분산 텐서의 교차항(σ²xy·σ²yz·σ²zx) — 미룬 이유: 원반에서 지배적인 것은 대각 성분이고, 교차항까지 들면 격자 배열이 3개에서 6개가 된다. 대각만으로 원반 두께와 Jeans 문턱이 나오는지 먼저 본다

- 성운의 RGB 3채널 확산 — 미룬 이유: 빛 확산을 채널마다 돌려야 해 FFT 가 세 배가 된다. 이번 판은 밝기 1채널
