## 충족 (0)

**이번 바퀴는 스펙 항목을 하나도 못 채웠다.** 구현은 들어갔지만 **화면에서 확인되지 않았다.**

## 구현한 것

`kScatterLight` — 별이 내는 빛을 화면 격자에 뿌린다.

```
별      L = (M/M_sun)^3.5
폭발 중  1e4 (초신성)
가스     0  (스스로 안 빛난다)
```

**이 지수 하나가 밀도 그림과 빛 그림을 갈라놓는다** — 태양 20배 별은 3만 6천 배 밝다.
밀도로 보면 알갱이 스무 개일 뿐인데 빛으로 보면 주변 수만 개를 합친 것보다 밝다.

**새 3D 격자도 FFT 도 안 만들었다.** 분산·속력이 이미 「알갱이 → 화면 격자」로 직접 뿌리는
길을 쓰고 있어(`kScatterDispersion`) 거기 얹었다. 비용은 CIC 4칸으로 같다.
설계 3.2 의 `lightSrc`/`lightOut` 별도 버퍼는 **반사광(별빛 확산)을 할 때 필요하고,
스스로 빛나는 것만 그리는 이 단계에서는 필요 없다.**

밝기 정규화도 밀도와 같은 경로를 쓰게 했다 — `L = M^3.5` 라 값 범위가 극단적이라
고정 배수로는 화면이 새까맣거나 새하얘진다.

## 막힌 것 — `colorBy=light` 가 화면에 반영되지 않는다

제어 채널로 `cmd=set` + `colorBy=light` 를 넣어도 `status` 가 계속 `density` 를 돌려준다.

| 보기 | status 의 colorBy | 켜진 픽셀 | 평균 밝기 |
|---|---|---|---|
| density 요청 | density | 13.4% | 7.5 |
| light 요청 | **density** | 11.1% | 6.7 |

두 그림이 다르긴 하지만(11.1% vs 13.4%) **그것은 35초 사이에 판이 변한 것이지 보기가
바뀐 것이 아니다.** `colorBy` 가 안 바뀌었으므로 둘 다 밀도 그림이다.

### 좁힌 범위

- **`ApplyLook` 이 덮어쓰는 것은 아니다** — `main.cpp:630` 에서 **시작 시 한 번만** 불린다.
  그래도 `look` 을 보존하도록 고쳐 두었다(그 자체로는 옳은 수정이다)
- `set` 블록 안에 처리를 넣었고 빌드는 통과한다. **`has(kv, "colorBy")` 가 참이 되는지,
  또는 그 블록이 실제로 실행되는지**를 다음 바퀴에서 확인해야 한다

**미검증을 충족으로 적지 않는다.** 커밋 메시지에도 「화면 연결은 아직 미검증」을 제목에 넣었다.
