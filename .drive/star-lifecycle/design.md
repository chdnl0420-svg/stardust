## 1. 데이터 구조

`pos.w` 와 `vel.w` 가 비어 있다(실측: `kCool` 이 `v.w` 를 보존만 함). 그 둘로 상태를 나눈다.

```
보이는 알갱이 400만
  pos.xyz  자리
  pos.w    0 = 가스 · >0 = 별(값이 질량) · <0 = 폭발 중(|값| 이 남은 연출 시간)
  vel.xyz  속도
  vel.w    ≥0 = 나이 · <0 = 잔해(백색왜성·중성자별, 더 이상 안 늙음)
  temp     전하(기존, 세 힘용)
  ash      재 함량                                    ← 새 배열 1개 (+ ashTmp)

암흑물질 1,200만
  dmPos, dmVel + 정렬용 dmPosTmp, dmVelTmp, dmKeys, dmOrder
```

**두 축으로 일곱 상태가 겹침 없이 갈린다** — 1판은 `vel.w` 부호 하나에 전부 욱여넣어
폭발 타이머가 0을 넘는 순간 신생 별 나이와 충돌했다(코덱스 지적).

### 1.1 `pos.w` 의 질량은 중력 질량이 아니다

**실측 확인**: `kScatter`(Sim.cu:295)는 `atomicAdd(&grid[...], w)` 로 **가중치만** 더한다.
질량 항이 없고, 퍼텐셜도 `potScale = gravity / allocN` 으로 총 개수 정규화를 쓴다.

그래서 **이 판에서 별 질량은 렌더·수명·최후 판정에만 쓴다.** 중력은 여전히 모든 알갱이가
같은 무게다. 중력에 반영하려면 `kScatter` 를 `w * mass` 로 바꾸고 정규화를 다시 잡아야 하는데,
그것은 이 판의 범위가 아니다(미룬 것에 적었다).

> 그래서 "태양 20배" 같은 표현은 **알갱이 20개가 모인 별**이라는 뜻이고, 실제 태양질량 단위가
> 아니다. 문서 전체에서 M 은 "그 별을 이룬 알갱이 수"다.

## 2. 물리 사슬 — 압력을 **텐서로** 넣는다

1판은 속도 분산을 **등방** 압력으로 되밀었다. 코덱스 지적대로 그것은 틀렸다 — Jeans 응력은
텐서고, 이웃 속도 차에는 원반의 차등회전·전단·스트리밍이 섞여 있어 등방으로 뭉개면
가짜 난류와 각운동량 이동, 수치 가열이 생긴다.

**그래서 빼는 대신 제대로 넣는다.** 두 가지를 고친다.

1. **평균 흐름을 뺀다** — `kCool` 이 이미 구하는 이웃 평균 속도 `v̄` 를 빼고 남은 잔차만 쓴다.
   차등회전과 전단이 여기서 제거된다
2. **방향별로 든다** — 하나의 σ² 가 아니라 σ²ₓₓ · σ²yy · σ²zz 세 개를 격자에 쌓는다
   (교차항은 원반에서 지배적이지 않아 이번 판에서는 뺀다)

```
σ²ᵢᵢ(격자) = < (v_i - v̄)ᵢ² >          방향별 잔차 분산
a_p        = -∇·(ρ σ²ᵢᵢ) / ρ          방향마다 따로 미분해 더한다
```

### 2.1 이렇게 하면 손으로 정한 숫자 셋이 사라진다

**압력을 넣는 진짜 값어치가 여기 있다.** 압력이 있으면 아래가 규칙이 아니라 결과가 된다.

| 지금 손으로 정하는 것 | 압력이 있으면 |
|---|---|
| `orbitDispersion = 0.085` (초기 속도에 섞는 난수) | **뺀다** — 압력이 그 자리를 채운다 |
| 별 문턱 "이웃 수 ≥ N" | **Jeans 조건** `M > M_J`, `M_J ∝ σ³/√ρ` |
| `diskThickness = 0.012` (원반 두께) | 수직 분산이 정한다 — 원반이 스스로 납작해진다 |

특히 **재 → 냉각 → 작은 별** 사슬이 저절로 나온다. `M_J ∝ σ³` 이라 식으면 Jeans 질량이
**세제곱으로** 급감한다.

```
재가 쌓임 → 잘 식음 → σ 작아짐 → M_J 급감 → 작은 별이 생긴다
```

1판은 이것을 "재가 많으면 냉각률을 올린다"는 규칙으로 **적어야** 했다. 압력이 있으면
적을 필요가 없다 — 1세대 별이 왜 거대했는지(σ 크고 M_J 큼)도 같은 식에서 나온다.
**원칙 1(연출 제거)이 여기서 가장 멀리 간다.**

### 2.2 사슬

```
1. 중력이 압력을 이기면 별이 된다 (Jeans)
2. 질량이 밝기·수명·최후를 정한다
3. 수명이 다하면 터진다
4. 터지면 재를 뿌리고 주변을 압축한다
5. 재가 쌓인 자리는 잘 식는다 → σ 가 내려가 1번의 문턱이 저절로 낮아진다
```

### 2.3 별 문턱 — Jeans 조건

`kCool` 은 이웃 27칸을 훑어 **평균 속도와 이웃 수**를 구한다(상한은 **27칸 합계 96개**다 —
1판에 "27칸 × 96" 이라 잘못 적었다). 거기서 잔차 분산도 함께 모은다.

```
M_local  = 그 자리 격자 밀도에서 낸 국소 질량
M_J      = k_J · σ³ / √ρ
M_local > M_J   →   pos.w = M_local, vel.w = 0
```

`k_J` 는 상수 하나뿐이고 격자 크기·96 절단에 좌우되지 않는다 — 1판의 "이웃 수 ≥ N" 이
그 둘에 통째로 휘둘렸던 것과 다르다.

**별 하나가 알갱이 하나다.** 안 A(표시만)에서는 조건을 만족한 **각 알갱이가** 별이 되므로,
밀집 무리 하나가 통째로 별이 된다. 1판의 "문턱 10이면 별 40만 개"는 틀린 계산이었다.
Jeans 조건은 σ 가 오르면 저절로 닫히므로 무한정 늘지는 않지만, **그래도 별 비율을 재서
5% 안팎을 벗어나면 `k_J` 를 조정한다.**

### 2.2 질량이 일생을 정한다

```
밝기 L = M^3.5,  수명 T = M^-2.5,  색 = 흑체(M 에서 유도)
```

M 은 그 별을 이룬 알갱이 수다(1.1 참조).

### 2.3 최후 — 셋으로 갈린다

| M | 최후 | 표시 |
|---|---|---|
| < 8 | 백색왜성 | `pos.w` 를 크게 줄이고 `vel.w = -1` (잔해). 작고 흰 점 |
| 8 ~ 20 | 중성자별 | 같은 방식, 더 작고 더 뜨겁다 |
| ≥ 20 | 블랙홀 | 아래 2.4 |

### 2.4 블랙홀 자리는 **여덟 개뿐이다**

`kMaxBlackHoles = 8`. 별이 대량으로 블랙홀이 되면 `addBlackHole` 이 **가장 가벼운 것을
조용히 밀어낸다** — 질량·운동량 보존이 깨진다(코덱스 지적).

그래서 이 판에서는 이렇게 한다.

- **블랙홀 전환에 별도 문턱을 둔다** — M ≥ 20 중에서도 **판을 통틀어 가장 무거운 것만**
  블랙홀이 되고, 자리가 없으면 **중성자별로 남는다**(밀어내지 않는다)
- 자리가 없어 중성자별로 남은 횟수를 세어 사고 기록에 남긴다

### 2.5 폭발

```
pos.w = -(연출 시간)        폭발 중으로 표시
그 무리에 바깥 방향 속도     흩어진다
ash 를 올린다                재를 뿌린다
주변 한 칸을 압축한다        다음 별의 방아쇠  ← 반경 1칸 고정, 상한 있음
```

**주변 압축에 반드시 반경 상한을 둔다.** 상한 없는 확산은 즉시 TDR 후보다(코덱스 지적).

연출 시간이 다하면 `pos.w = 0`(가스로) 또는 잔해면 `pos.w > 0, vel.w < 0`.

### 2.6 재가 냉각률을 정한다

```
coolingRate_local = coolingRate × (1 + ash × k_ash)
```

여기서 사슬이 처음으로 돌아온다.

### 2.7 커널을 나눈다

**별 생성·폭발을 `kCool` 에 얹지 않는다.** 한 커널에 분기와 전역 쓰기가 몰리면 같은 무리가
동시에 폭발할 때 한 셀에 대량 경합이 생긴다(코덱스 지적).

```
kCool        (있음) 이웃 평균 속도 + 이웃 수 → 냉각, 그리고 이웃 수를 배열에 남긴다
kStarForm    그 이웃 수를 읽어 별 판정만 한다 (이웃 훑기 없음)
kStarAge     나이 갱신 + 최후 판정
kExplode     폭발 처리 (반경 1칸 고정)
```

`kStarForm` 부터는 **이웃을 다시 훑지 않는다** — `kCool` 이 남긴 값을 읽기만 하므로 O(N).

## 3. 렌더

### 3.1 별빛과 성운

```
밝기 = L = M^3.5,  색 = 흑체
```

성운은 반사 + 발광 둘만(암흑성운은 미룬 것).

### 3.2 빛 FFT 는 **별도 버퍼가 필요하다**

1판에 "중력 푸아송과 같은 파이프라인이라 새 자료구조가 없다"고 적은 것은 **틀렸다** —
중력은 `rho → specRho → pot` 를 파괴적으로 쓴다(코덱스 지적).

```
lightSrc   별빛 소스 격자 (G³)
lightOut   확산 결과 (G³)
+ cuFFT 작업공간 (기존 플랜 재사용 가능 여부는 구현 때 실측)
```

색은 스칼라 하나로 부족하므로 **이번 판은 밝기 한 채널만 확산시키고 색은 소스의 평균 색을
쓴다.** RGB 3채널 확산은 미룬 것.

### 3.3 밝기 기준을 백분위수로

지금은 「값 있는 칸의 평균」이라 초신성 하나가 기준을 끌어올린다. 상위 5% 지점으로 바꾼다.

### 3.4 줌 자동 전환 (안 A)

데이터는 하나고 보이는 방식만 바뀐다. 전환에 이력을 건다(절반 해상도 토글의 패턴).

## 4. 엔진 — 예산·상한·워치독

### 4.1 예산 33.3ms (30프레임)

`kStepBudgetMs = 16.7 → 33.3`.

### 4.2 상한 공식에서 SM 항 제거

```
cap = byMemory        ← 그 뒤 프레임 예산으로 이분법 조임(기존 그대로)
```

### 4.3 경계와 격자

| 장면 | 경계 | 격자 |
|---|---|---|
| 은하 | 고립 | **128 고정** (400만을 넘어도 안 올린다) |
| 우주 구조 | 주기 | 256 |

### 4.4 워치독 — **절대 상한을 함께 건다**

```
DANGER_STEP_MS = min(정상 스텝 중앙값 × 64,  250ms)
```

**1판은 여기서 치명적이었다.** "정상 스텝 × 64" 만 쓰면 예산 33.3ms 에서
33.3 × 64 = **2,131ms = 2.13초** 로 Windows TDR 기본값(2초)을 **넘는다**.
안전장치가 안전선 밖으로 나간다. 절대 상한 250ms 를 함께 걸어 그 일이 없게 한다.

**그리고 이 워치독은 스텝이 끝난 뒤에야 잰다** — 이미 달리기 시작한 단일 폭주 커널은
못 막는다. 그래서 아래 7장의 커널별 상한이 진짜 방어선이다.

## 5. 걷어내는 것

| 갈래 | 대상 | 처리 |
|---|---|---|
| **연출** | **`diskPoint()` 의 나선팔 배치** | **로그 나선 각 변형과 팔 밀도 대비(cos2Δ·cos4Δ)를 빼고 매끄러운 원반으로** |
| 연출 | `spiralWave` | 제거 |
| 연출 | `kOrbitAroundBH` | 제거 |
| 근사 | `haloEnabled` | 제거. 암흑물질을 알갱이로 |
| 과장 | `blackHoleMassScale = 1/50` | 1 로 |
| 압력 대역 | `orbitDispersion = 0.085` | **제거** — 압력 텐서가 그 자리를 채운다 |
| 손으로 정함 | `diskThickness = 0.012` | **제거** — 수직 분산 σ²zz 가 두께를 정한다 |
| — | 블랙홀 삼킴 반경의 격자 한 칸 바닥 | **그대로 둔다 — 이것은 과장이 아니라 안전장치다** |

**나선팔 초기 배치가 1판에서 빠진 가장 큰 연출이었다.** `diskPoint()`(Sim.cu:121)가
로그 나선 `psi = ln(r/R₀)/tanI`(감김각 16°)로 각을 배치하고 `-(A/2)·sin(2Δ)` 로 당겨
밀도에 `1 + A·cos(2Δ) + B·cos(4Δ)` 를 만든다. `spiralWave` 를 지워도 이것이 남았다.

**블랙홀 지평선 부풀림을 실제 식으로 되돌리는 것은 뺐다.** 지금 구조에서 삼킴 반경의
격자 한 칸 바닥과 세제곱근 성장은 **한 셀 집중 atomicAdd 를 막는 안전장치**이고,
그것을 없애면 과거 재부팅 조건이 되살아난다(코덱스 지적).

## 6. 데이터 흐름 (한 스텝)

```
정렬(셀 순서) — 보이는 알갱이 + 암흑물질
  ↓
kScatter        알갱이 → 밀도 격자 (둘 다, 모두 무게 1)
  ↓
푸아송 FFT      밀도 → 퍼텐셜 → 격자 가속도
  ↓
kCool           이웃 훑기 — 냉각 + 이웃 평균 v̄ + 방향별 잔차   (합계 96 상한)
  ↓
kDispScatter    잔차 분산을 격자에 쌓기 (σ²xx·σ²yy·σ²zz)    (O(N), CIC 8칸)
kPressure       격자 기울기 → 압력 가속도                    (O(cells), 이웃 6칸)
  ↓
kStarForm       Jeans 조건 M > k_J·σ³/√ρ 로 별 판정          (O(N), 이웃 훑기 없음)
kStarAge        나이 +dt, 수명 넘으면 최후 판정              (O(N))
kExplode        폭발 처리 — 반경 1칸 고정                    (O(N) × 상수)
  ↓
kIntegrate      가속도 적용, 광속 상한, 위치 갱신
  ↓
[렌더] kScatterLight → 빛 FFT(별도 버퍼) → 흑체색 + 성운 → 백분위수 → 줌 전환
```

## 7. 안전 — 이 앱은 버그가 PC를 재부팅시킨다

- **새 커널마다 비용 주석과 상한.** `kStarForm`·`kStarAge` 는 O(N) 이고 이웃을 안 훑는다.
  `kExplode` 의 주변 압축은 **반경 1칸 고정**이다
- **`kPressure` 는 격자 커널이라 알갱이 수와 무관하다.** 이웃 6칸만 보고 상한이 구조적으로
  걸려 있다 — 뭉친 자리에서 폭주하는 경로가 없다. `kDispScatter` 는 CIC 8칸으로 `kScatter` 와
  같은 비용이다
- **압력 가속도에도 상한을 건다** — `kIntegrate` 의 광속 상한 앞에서 `kMaxNewAcc` 로 자른다.
  분산이 튀는 순간 힘이 발산하는 경로를 막는다
- **`cudaMalloc` 직후 초기화** — `ash`, `dm*`, `lightSrc`, `lightOut`, `disp[3]` 전부
- **분산 격자는 패딩을 안 쓴다.** 푸아송은 전역이라 고립 경계에서 256³(8배)로 부풀지만,
  압력은 **이웃 6칸만 보는 국소 미분**이라 128³ 그대로다. 배열 3개 × 128³ × 4B = **25MB**,
  커널은 209만 스레드. 패딩을 그대로 따라갔다면 1,677만 스레드가 될 뻔했다
- **`estimateBytes` 에 새 배열을 전부 반영** — 안 하면 상한 계산이 실제보다 큰 값을 허락한다
- **정렬 주기를 늘리지 않는다** — 매 스텝 정렬은 과거 드라이버 붕괴 원인이다
- **광속 감시(30초)와 워치독(정상 × 64, 상한 250ms)을 유지**

## 8. 확인 방식 — 눈과 수치, 그리고 **보존량**

1판의 "스크린샷 + nvlddmkm 0건"은 물리·안전 검증으로 부족하다(코덱스 지적). 아래를 더한다.

| 무엇 | 어떻게 |
|---|---|
| 별 생성 | `starCount()` — **지금 `return 0` 이라 실제 구현이 필요하다** |
| 질량 보존 | 가스 + 별 + 잔해 + 블랙홀 삼킨 수 = 총 알갱이 수 (매 바퀴 확인) |
| 총 운동량 | 폭발 전후로 보존되는지 |
| NaN/Inf | 알갱이 위치·속도에 하나라도 있으면 실패 |
| 셀별 최대 점유수 | 한 칸에 몰린 수 — atomicAdd 경합의 선행 지표 |
| 커널별 시간 | `stepMs` 만이 아니라 커널별로 — 어느 것이 먹는지 보여야 고칠 수 있다 |
| **프레임 시간** | `stepMs` 는 렌더를 **포함하지 않는다.** `frameMs` 를 함께 본다 |
| 블랙홀 자리 부족 | 자리가 없어 중성자별로 남은 횟수 |

**성능 판정은 추정이 아니라 실측이다.** 1판의 "6.2ms" 는 단순 대역폭 식이고 CIC atomicAdd
경합·정렬·이웃 탐색·렌더·동기화가 전부 빠져 있었다. **알갱이를 100만 → 400만 → 800만 →
1,600만으로 단계적으로 올리며 각 단계에서 재고, 예산을 넘으면 거기서 멈춘다.**
