# star-lifecycle — 요구사항 (2번 칸 · deep-interview)

앞 칸 산출물(`handoff.md` · `log.md`)을 읽고, 실측으로 확인한 뒤 좁힌 결과다.
**결정**과 **열린 질문**을 구획으로 나눠 적는다 — 섞으면 `spec-trace` 가 열린 질문을 누락으로 올린다.

---

## 결정

### D1. 목표

**라이프 사이클을 넣고, 그 규칙들이 모여 나머지가 저절로 나오게 한다(창발).**
겨냥하는 그림은 "실제 밤하늘에서 돌아가는 방식을 눈으로 보는 것" — 예쁜 그림이 아니라
**왜 저게 저기서 빛나는지가 보이는** 우주.

### D2. 범위 — 전부

세 축을 이번 판에 다 넣는다.

1. **물리 다섯 칸** — 압력 → 별 문턱 → 질량별 최후 → 폭발(재 + 충격파) → 재가 냉각률을 정함
2. **빛으로 보기** — 밀도가 아니라 복사로 그린다. 가스는 반사광으로 보인다
3. **줌 자동 전환** — 멀리서는 별 점, 파고들면 그 별을 이루던 가스 덩어리

### D3. 연출·근사·과장을 전부 제거한다

사용자 원칙 두 개가 이 판을 지배한다.
- **연출은 제거한다**
- **원하는 게 안 나오면 현실에서 빠진 것을 찾아 하나씩 넣는다**

제거 대상(실측으로 사용 여부 확인함 — Sim.cu 기준):

| 갈래 | 대상 | 실측 |
|---|---|---|
| 연출 | `spiralWave` 회전 밀도파로 나선팔을 직접 그림 | 2회 사용 |
| 연출 | `kOrbitAroundBH` 블랙홀 놓을 때 둘레에 궤도 속도를 억지로 줌 | 3회 사용 |
| 근사 | `haloEnabled` 암흑물질을 알갱이 대신 배경 힘으로 | 3회 사용 |
| 과장 | 블랙홀 지평선 부풀림 (`blackHoleRs` 기반) | 사용 중 |
| 과장 | 블랙홀 무게 `blackHoleMassScale = 1/50` | 사용 중 |
| 압력 대역 | `orbitDispersion` — 주석에 "압력 노릇을 해 파편화를 막고 나선팔을 자라게 한다" | 1회 사용 |

### D4. 암흑물질은 빛 안 내는 알갱이로 넣는다

`halo`(배경 힘)를 뺀 자리를 중력은 주고받되 빛은 안 내는 알갱이로 채운다.
"빠진 현실을 찾아 넣는다"는 원칙에 맞고, 헤일로가 원반을 붙잡는 것이 저절로 나온다.

### D5. 그림이 무너지면 세 바퀴까지 찾아 넣는다

연출을 다 걷어내고 원하던 그림이 안 나오면, **빠진 현실을 찾아 넣는 것을 세 바퀴까지** 한다.
그래도 안 되면 무엇이 모자랐는지 기록하고 다음으로 넘어간다 — 판은 끝낸다.

### D6. 완료 기준 — 사이클 한 바퀴 + 수치, 둘 다

- **눈으로**: 가스가 뭉쳐 별이 되고, 무거운 별이 먼저 터지고, 그 자리에서 새 별이 태어나는 것을
  스크린샷으로 확인
- **수치로**: 별 개수·재 분포 같은 값으로도 확인
- 둘 중 하나만으로는 통과가 아니다 — "보이긴 하는데 숫자는 이상한" 경우를 걸러야 한다

### D7. 프레임 예산을 30프레임(33.3ms)으로 올린다

`App::init` 의 `kStepBudgetMs = 16.7` → **33.3**.

실측 근거 (이 카드 608 GB/s, 공식 `(20·cells·4 + 개수·80) / (대역폭·0.7)`):

| | 격자 | 실제 도는 크기 | 격자 비용 | 상한 | 정상 스텝 |
|---|---|---|---|---|---|
| 지금 60프레임 | 128 | 256³ | 3.15ms | 399만 | 3.9ms |
| **30프레임** | 256 | 512³ | 25.2ms | (아래 D8 참조) | 약 26ms |

400만이 벽이었던 것은 하드웨어가 아니라 `ApplyAutoGrid` 의 `particleCount >= 4000000 ? 256 : 128`
문턱과 고립 경계 패딩(8배)의 조합이었다.

### D8. 상한 공식에서 SM 공식을 뺀다

지금: `cap = min(byMemory, bySpeed)` — `bySpeed = SM개수 × 100,000`
바꿈: **`bySpeed` 를 지운다.** 남는 것은 **메모리 한계**와 **한 프레임 예산** 둘뿐.

`SM × 10만` 은 근거 없는 어림이고, 예산 계산이 이미 속도를 반영한다.
30프레임 + 격자 256 이면 예산상 4,300만까지 부르다가 **메모리 한계(약 3,599만)** 에서 멈춘다.

### D9. 워치독 문턱을 정상 스텝에 연동한다

지금 `DANGER_STEP_MS = 250.0f` 고정. **"정상 스텝의 몇 배"로 바꾼다.**

예산을 늘리면 정상 스텝이 3.9ms → 26ms 로 오르는데, 문턱이 고정이면 안전 여유가
**512배 → 77배**로 줄고 워치독까지의 배수도 64배 → 10배가 되어 오탐이 는다.
정상 스텝에 연동하면 예산을 바꿔도 감지 성격이 유지된다.

## 열린 질문

### Q1. 알갱이 개수 배분 (D8 이후 전제가 바뀌었다)

인터뷰 중간에 "총수는 그대로(400만) 두고 보이는 것 1 : 암흑물질 4~5 로 나눈다"로 한 번 정했으나,
그 직후 **D7·D8 로 상한 자체가 달라졌다.** 메모리 한계(3,599만)까지 열리면 총수를 늘려
보이는 알갱이를 지금만큼 두면서 암흑물질을 얹을 수 있다.
**설계 단계에서 실측(예산·메모리·실제 스텝)한 뒤 정한다.**

### Q2. 경계를 어떻게 쓸 것인가

`maxGridSize(Isolated) = 256`(실제 512³) · `maxGridSize(Periodic) = 512`(패딩 없음).
**주기 경계의 격자 256 은 고립 경계의 격자 128 과 계산량이 같다.**
은하 장면은 텅 빈 우주에 홀로 떠 있어야 해서 고립이 맞고, 우주 구조 형성은 원래 주기다.
장면마다 다르게 갈지, 하나로 통일할지 안 정했다.

### Q3. 워치독 연동 배율

D9 에서 "정상 스텝의 몇 배"로 바꾸기로 했으나 그 배수를 안 정했다.
지금 값(250ms)은 3.9ms 기준 64배다.

### Q4. 성운 세 종류 중 어디까지

**반사성운**(별빛 산란, 푸르스름) · **발광성운**(자외선이 수소를 이온화, 붉음) ·
**암흑성운**(뒤쪽 빛을 가려 실루엣 — 밀도가 높을수록 오히려 검다).
셋 다 할지, 반사만 할지 안 정했다.

### Q5. 초신성이 화면 밝기 기준을 삼키는 문제

초신성은 은하 전체보다 밝다(별 1000억 개 합친 것보다, 몇 주 동안).
지금 밝기 기준이 「값 있는 칸의 평균」이라 그런 별 하나가 나머지를 다 어둡게 만든다.
실제 천문 사진은 노출을 여러 장 겹쳐(HDR) 푸는데, 여기서 어떤 손질을 할지 안 정했다.

### Q6. 백색왜성·중성자별은 화면에서 무엇으로 보이나

질량별 최후가 셋으로 갈리는데(백색왜성/중성자별/블랙홀) 앞의 둘을 어떻게 그릴지 안 팠다.

### Q7. 별이 모여 은하가 되는 과정 자체

첫 요청에 있었으나 대화에서 안 팠다. 지금 판은 은하가 이미 깔린 상태에서 시작한다.

## 실측으로 확인한 코드 상태 (2026-08-16)

`Sim.cu` 에서의 사용 횟수 — handoff 의 기술 사실이 맞는지 직접 셌다.

| 심볼 | 횟수 | 뜻 |
|---|---|---|
| `starFormationEnabled` | **0** | 설정에만 있고 코어 미구현 |
| `temperatureEnabled` | **0** | 〃 |
| `pressureEnabled` | **0** | 〃 |
| `checkCollapse` | 3 | 밀도 문턱 넘으면 블랙홀 — 있음(기본 꺼짐) |
| `kCool` | 2 | 냉각 — 이번 판에서 구현되어 돎. 뭉침을 만드는 유일한 장치 |
| `collapseEnabled` | 1 | 있음 |
| `orbitDispersion` | 1 | 있음(압력 대역) |
| `spiralWave` | 2 | 있음(연출) |
| `haloEnabled` | 3 | 있음(근사) |
| `kOrbitAroundBH` | 3 | 있음(연출) |
| `bulgeFraction` | 1 | 있음 |

- `starCount()` → `return 0`, `measureMeanTemperature()` → `return 0.0`
- 격자 128³. 격자 한 칸(판의 0.78%)보다 작은 구조는 원리적으로 표현되지 않는다
- 절반 해상도 토글에 **이력** 패턴이 있다 → 줌 전환 팝핑에 재사용 가능
- `kInitCharge` 가 알갱이 번호 해시로 값을 깐다 → 줌 쪼개기의 결정론적 난수에 재사용 가능
- `kCool` 이 이미 이웃과의 속도 차를 재고 있다 → **압력도 같은 커널에서 나올 수 있다**
  (별 계에서 압력은 속도 분산 텐서 — 진스 방정식)
